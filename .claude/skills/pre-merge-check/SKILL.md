# 머지 전 확인

MSG는 main에 머지하는 순간 운영 주소가 바뀌고, 제출한 결과물이 그대로 사전평가와 본선 시연에 쓰인다(일정은 루트 `CLAUDE.md` "지금 단계"). 대상 PR은 인자로 받은 번호, 없으면 지금 브랜치의 PR이다. 아래를 차례로 확인하고 항목마다 통과·확인 필요·문제로 표시한다. 머지는 하지 않는다.

1. **한 PR에 한 기능:** `gh pr view`와 `gh pr diff --name-only`로 바뀐 파일을 보고, 서로 관계없는 변경이 섞였으면 알린다.
2. **CI:** `gh pr checks`가 모두 통과했는지 본다.
3. **작게 나눴는지:** 로그인 흐름, 큰 리팩토링, API 응답 형식 변경이 들어 있으면 PR이 작게 나뉘었는지, 테스트가 함께 들어갔는지 본다. API 응답 형식이 바뀌었으면 `api-contract-checker` 에이전트로 프론트 타입·목업·문서를 대조한다.
4. **PR 미리보기 체험 모드:** PR 댓글의 Vercel 미리보기 주소를 찾아 사용자에게 알려 주고, 체험 모드에서 바뀐 화면을 확인했는지 묻는다. 사용자가 요청하면 내장 브라우저로 직접 열어 확인한다.
5. **제출 자료:** 화면이 바뀌는 PR이면 노션 제출 페이지와 시연 영상도 고쳐야 하는지 사용자에게 묻는다.
6. **제출 직전 큰 변경:** 오늘이 제출 마감에 가깝고 변경이 크면 머지를 미루자고 말한다.
7. **상대방 알림:** API·DTO처럼 상대방 작업에 영향을 주는 변경이면 PR 본문에 적혀 있는지 본다.

끝에 확인 필요·문제 항목만 짧게 다시 모아 보여 준다.
